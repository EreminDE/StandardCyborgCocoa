# Сканер культи: первый этап

Нативное приложение iOS на основе TrueDepthFusion / StandardCyborgCocoa.
Целевое устройство — iPhone 13, фронтальная TrueDepth. Сканируется культя на пациенте.

## Реализовано

- Русская главная страница, инструкции, переходы в библиотеку и настройки.
- Ручной старт сразу по нажатию, без обратного отсчёта. Повторное нажатие завершает скан.
- Ручной режим включён по умолчанию. Полное разрешение глубины выключено, как в исходном TrueDepthFusion. Явные ранее сохранённые настройки сохраняются.
- Защита от старта до готовности камеры и повторного старта во время финализации.
- Кнопка «Готово» во время съёмки открывает результат; она больше не закрывает экран одновременно с финализацией.
- При уходе приложения с переднего плана съёмка завершается; предпросмотр ожидает возвращения приложения.
- Сохранение геометрии через временный файл, уникальные имена, обработка ошибки записи без закрытия результата.
- Библиотека сохранённых PLY, просмотр 3D, удаление с подтверждением и обработкой ошибки.
- Экспорт из предпросмотра: исходный PLY в метрах; бинарный STL в миллиметрах без цвета.
- Поверхность строится локально из PLY, в том числе после перезапуска приложения. Параметр `closed = false`: намеренно не заполнять незаснятые области искусственной крышкой. Это не гарантирует отсутствие всех интерполяций Poisson-реконструкции.
- Загрузчик SCMesh поддерживает геометрический PLY без UV/текстуры, проверяет индексы и восстанавливает отсутствующие нормали/цвета.
- IPA собирается в GitHub Actions с проверкой уникальности Bundle ID и удалением только идентичных дубликатов ресурсов.

На экране библиотеки действие PLY по свайпу использует существующий ZIP-экспорт. Несжатый PLY и STL доступны из 3D-предпросмотра.

## Границы первого этапа

Алгоритм регистрации кадров в этом этапе не меняется. Патч ориентации взят из `fix/truedepth-orientation-iphone13`; его физическую корректность ещё нужно проверить на iPhone.
Эксперименты `feature/icp-stability-v1` не включены.
Автоматическое восстановление трекинга, пауза с безопасным продолжением, именованные проекты, обхваты, длина, сечения, оценки полноты поверхности и CAD/заказы пока не реализованы.
Построенная поверхность хранится в памяти предпросмотра; после повторного открытия скана она строится заново из исходного облака.
STL — результат реконструкции, а не подтверждение точности измерений или пригодности для изготовления гильзы.

## Автоматическая проверка

Workflow: `.github/workflows/build-limb-scanner.yml`.

1. Компилирует и выполняет независимые Swift-проверки STL: структура бинарного файла, перевод метров в миллиметры, ориентация нормали, вырожденные грани, пустые/обрезанные буферы, некорректные индексы и NaN.
2. Собирает приложение для `generic/platform=iOS` в Release, Xcode 16.4, без подписи.
3. Упаковывает `LimbScanner.ipa` с ID `com.ereminde.limbscanner.dev`.
4. Проверяет уникальность Bundle ID во всём `.app`.

Это проверка сборки для устройства, а не запуск на iPhone или симуляторе.

## Проверка на iPhone 13

- Установить IPA с собственной подписью через используемый установщик. Это отдельный ID приложения; ранее сохранённые сканы другой сборки автоматически не переносятся.
- Первый запуск: разрешение камеры; отказ → понятное сообщение и переход в настройки.
- В ручном режиме нажать старт: скан начинается сразу. Через 15 секунд он продолжает работать. Повторное нажатие открывает результат.
- Повторить старт → «Готово» и быстрые повторные нажатия; не должно быть двойной финализации или пропажи результата.
- Сохранить → закрыть экран съёмки → библиотека → открыть сохранённый скан.
- Перезапустить приложение; проверить наличие скана и возможность построить поверхность и экспортировать STL.
- Проверить «Отмена» при построении поверхности и повторный запуск построения.
- Экспортировать PLY и STL через «Поделиться», открыть файлы в CAD. Проверить масштаб на объекте известного размера, например 100 мм; STL должен открываться в миллиметрах.
- Сравнить RGB, глубину и геометрию на несимметричном объекте с отметками «верх» и «право»: исключить поворот на 90° и зеркальность.
- Свернуть приложение во время съёмки и вернуться: результат должен дождаться возвращения.
- Проверить режим таймера, если ручной режим выключен в настройках.
- Проверить потерю трекинга: по умолчанию срабатывает существующая остановка, автоматического продолжения нет.
- Удаление отменить, затем подтвердить; остальные сканы должны сохраниться.

## Следующие этапы

1. Проверить ориентацию и масштаб на устройстве; записать воспроизводимые RGB-D-последовательности для сравнения алгоритмов.
2. В отдельной ветке улучшить трекинг: оценка качества, фильтрация выбросов, coarse-to-fine ICP, прогноз ориентации по Core Motion, контролируемое восстановление.
3. Добавить проекты, метаданные и версии сканов; хранить результаты измерений отдельно от исходной геометрии.
4. Ввести сечения, длину/обхваты, контроль покрытия и проверку воспроизводимости на эталоне.
5. После проверки точности — передача моделей и параметров в CAD/заказы.

## Регрессия зернистости (4 ноября 2026)

Пользователь сообщил о более рябой поверхности при более стабильном изображении. В первом этапе по умолчанию было включено `full_resolution_depth_frames`: предел выбора глубины менялся с 320 до 640, а `reconstructSingleDepthBuffer` в предпросмотре получал `smoothingPoints: false` вместо `true`. В рендерере размер точек также зависит от разрешения глубины. Возвращён исходный default `false` во всех четырёх местах настройки. Явно сохранённый выбор пользователя сохраняется; для сравнения его нужно выключить вручную и создать новый скан.

В накоплении кадров `computeFrameValues` использует прежний default `smoothPoints = false`; отключение сглаживания предпросмотра не доказывает причину ряби накопленной модели. ICP и фильтрация AVCaptureDepthDataOutput в этой ветке не менялись. По скриншоту нельзя измерить погрешность. Нужен сравнительный скан неподвижного матового объекта известного размера при одинаковом расстоянии, освещении и длительности, с оценкой исходного PLY отдельно от построенной поверхности.
